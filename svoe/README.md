# СВОЁ — семейные финансы на VPS

Это отдельное PWA-приложение с личными и семейным бюджетами. Работает на `/svoe/` существующего сайта: `https://zampolit73.duckdns.org/svoe/`.

## Деплой

Workflow `.github/workflows/deploy-svoe.yml` запускается после успешного основного GitHub Actions production-пайплайна. Он повторно использует существующие repository secrets `VPS_HOST`, `VPS_USER`, `VPS_PWD`. Секреты не хранятся в коде и не выводятся в лог.

Архив исходников `svoe/source.tar.gz.b64` декодируется на GitHub runner, передаётся по SSH и запускается как отдельный systemd-сервис `svoe`, который слушает только `127.0.0.1:8765`.

В существующий SSL vhost добавляется исключительно маршрут `/svoe/`, ведущий к отдельному Python-сервису. Проверка `nginx -t` обязательна; в случае её ошибки старый конфиг восстанавливается. Другие пути не удаляются, другие сервисы не перезапускаются.

SQLite-файл расположен в `/opt/svoe/data/svoe.sqlite`, не включён в GitHub и не удаляется при последующих деплоях.

## Приватность и вход

- Первый аккаунт создаётся **только через секретную одноразовую ссылку** с параметром `setup`. Значение токена не публикуется в GitHub; там хранится только его хеш.
- После регистрации первого владельца самостоятельная регистрация закрыта. Второй пользователь подключается по приглашению владельца.
- Личные операции и цели хранятся под `p:<user_id>`; общие — под `f:<family_id>`.
- Переход к семейному бюджету по умолчанию назначен на 1 декабря 2026 года. Личная история не объединяется автоматически.
- Куки `HttpOnly`, `SameSite=Strict`, `Secure` при HTTPS, `Path=/svoe`.

## Что ещё нужно до регулярной эксплуатации

- Настроить ежедневные защищённые резервные копии SQLite с проверкой восстановления.
- Включить мониторинг ошибок и обновлений ОС.
- Провести дополнительную проверку безопасности перед хранением реальных финансовых данных.

Не храните пароли, личные финансовые выписки и базу SQLite в репозитории.

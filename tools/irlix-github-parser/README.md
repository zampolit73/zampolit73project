# IRLIX GitHub Outstaff Parser — MVP v0.1

Независимый и бесплатный CLI-парсер открытых GitHub-репозиториев для B2B Sales Intelligence компании «Ирликс». **Не CRM, не интеграция с существующим сайтом и не автоматическое доказательство договоров**.

**Стартовая контрольная точка:** 394 прогона, 416 исключённых repo, очередной №395. Архив состояния: `data/github-outstaff-intelligence/snapshots/github_outstaff_intelligence_handoff_394_2026-10-26.zip` (в корне основного репозитория). Первые 15 прогонов старого исследования были тематическими; новая автоматизация считает только реально открытые уникальные repo.

## Возможности

- Находит кандидатов через официальный GitHub REST API: поиск репозиториев по README и датам создания; **при наличии `GITHUB_TOKEN`** также поиск кода (`/search/code`).
- Не платит сторонним API, не использует прокси, обход CAPTCHA, scraping HTML GitHub или LLM API.
- Импортирует **все 416** исторических исключений (case-insensitive), не повторяет их.
- Засчитывает прогон **только после скачивания и декодирования содержимого файла**; поиск без открытия не считается.
- В транзакции SQLite сохраняет номер и метаданные **после каждого repo**, фиксирует очередь поиска и точку продолжения даже посередине страницы.
- Если результаты поиска упираются в ограничение 1000/запрос, дополнительно делит запросы о репозиториях по диапазону `created`.
- Извлекает упоминания заказчиков/поставщиков, стеков, источник и короткий фрагмент; автоматический скоринг **консервативный**: максимум **C**, A/B требуют аналитика и оригинального источника.
- Не сохраняет весь текст README/CV; скрывает найденные email/телефоны и `@handles` в выдержках.
- Выгружает Excel-совместимые `checked_repos.csv`, `sales_review_queue.csv`, `excluded_repositories.txt`, `STATUS.md`.

## Запуск на Ubuntu (VPS) или Windows, Python 3.10+

Из корня `zampolit73project`:

```bash
python3 tools/irlix-github-parser/parser.py init \
  --archive data/github-outstaff-intelligence/snapshots/github_outstaff_intelligence_handoff_394_2026-10-26.zip
python3 tools/irlix-github-parser/parser.py scan --max-repos 50 --mode repo
python3 tools/irlix-github-parser/parser.py export --out runtime/irlix-outstaff-exports
python3 tools/irlix-github-parser/parser.py stats
```

SQLite по умолчанию лежит в `runtime/irlix-github-parser.sqlite` (относительно рабочего каталога). **Не коммитить SQLite, исходные CV, приватные документы, токены, полные тексты файлов.** Лучше задать `--db /путь/вне/публичного/webroot/parser.sqlite` *перед подкомандой*, например `python3 tools/.../parser.py --db /srv/irlix/parser.sqlite scan --max-repos 50`.

Windows PowerShell: замените `python3` на `py -3`; обратные слэши переноса команд Bash уберите. CSV — UTF-8 с BOM, корректно открываются в Excel.

### Рекомендовано: бесплатный GitHub API-токен (не обязательно)

Без токена работает поиск **репозиториев**, но у GitHub низкий лимит на публичные API-запросы. **Поиск кода требует авторизации**. Для увеличения пропускной способности используйте personal access token с минимальными нужными правами; публичные репозитории достаточно читать. *Не пишите токен ни в файл проекта, ни в команду, которая попадает в history, и не загружайте его в GitHub*:

```bash
read -rs GITHUB_TOKEN && export GITHUB_TOKEN
python3 tools/irlix-github-parser/parser.py scan --max-repos 50 --mode hybrid
unset GITHUB_TOKEN
```

В PowerShell токен можно ввести через защищённую переменную среды; храните секреты в собственном менеджере секретов. **Токен существующего ChatGPT/GitHub-коннектора автоматически не передаётся обычному Python-скрипту.**

GitHub отдельно лимитирует код-поиск (до 10 запросов/минуту), обычный поиск (аутентификация до 30/мин) и Core API. Парсер ограничивает частоту сам, при 403/429 от лимита **останавливается с сохранённым состоянием**. Повторный запуск возобновляется с места остановки. Поиск имеет окно максимум 1000 результатов на запрос; не гарантируется, что существует 50 000 релевантных доступных репозиториев. См. https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api и https://docs.github.com/en/rest/search/search.

## Результаты и ручная проверка

`checked_repos.csv`: № прогона, репо, проверенный файл, C/D/X, гипотеза, ограничения, Sales-действие, оценка, первичный URL. `sales_review_queue.csv`: только приоритетные кандидаты, где рядом с outstaff обнаружен известный заказчик (еще **не подтверждённый контракт**). В новых автоматических записях уровни **A/B намеренно не назначаются**. Проверяйте источник, год, юрлицо, модель работ и текущую потребность, прежде чем писать клиенту.

**Excel на 61 вкладке** из checkpoint №394 остаётся без изменений. Этот MVP выпускает CSV для дальнейшего объединения с общей книгой (через отдельный XLSX-merge шаг в ChatGPT). Он пока **не публикует обновления в GitHub автоматически**, не пишет в Laravel/SQLite сайта и не запускается по расписанию; это безопасный standalone пилот. Для стабильных 50 000 прогонов потребуются тесты запросов, нормализация источников и ручная верификация хороших лидов.

## Тесты без сети

```bash
cd tools/irlix-github-parser
python3 -m unittest -v test_parser.py
```

Ограничения: `created`-шардирование только для поиска **репозиториев**, не для `/search/code`; код-поиск ограничен 1000 результатами на запрос. GitHub может не вернуть все репозитории из-за особенностей индексации и результатов поиска. Сканер не делает заключения о заключении договоров; это задача Sales Intelligence.

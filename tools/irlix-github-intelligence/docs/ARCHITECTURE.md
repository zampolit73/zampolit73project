# Архитектура и продолжение разработки

Standalone Python 3.10+ CLI. Не интегрирован в Laravel-сайт и не развёрнут на VPS. Единственный постоянный компонент — SQLite. HTTP-клиент на стандартной библиотеке, без платных сервисов.

Поток: queries/seeds → REST Search → публичность репозитория → commit default branch → tree → кандидаты → blob → извлечение в отдельном процессе → коммерческие сигналы → SQLite → отчёты.

Модули:

- github.py: только GET к api.github.com, запрет перенаправлений с токеном, бюджеты, Retry-After, primary/secondary limits, обход усечённого дерева.
- queries.py: два профиля поисковых запросов.
- pipeline.py: durable discovery, очередь документов, локальная загрузка, продолжение, разбиение насыщенных code queries по size.
- extract.py / extract_worker.py: чтение форматов, единицы доказательств и лимиты; макросы/JS не исполняются. У объектов опыта JS/TS сохраняются границы компании и isOutstaff.
- analyze.py: роли сторон, ставки/зарплаты/суммы, даты, договоры, признаки географии и спроса; консервативная классификация.
- store.py: SQLite и межпроцессная блокировка. Находки и статус файла записываются одной транзакцией.
- exporter.py: CSV/JSON/XLSX и HTML-обзор. Экранирование HTML, запрет активных формул из входных данных.
- cli.py: команды, конфигурация, протокол прохода.

Идентификатор документа = SHA256(repo + path + blob SHA). Идентификатор находки = SHA256(document ID + locator). Повторная обработка версии обновляет находки атомарно. Проверки человека хранятся отдельно. Идентичные документы в других репозиториях сохраняются с собственными источниками и получают duplicate_of в экспорте.

Статусы files: pending, done, no_signal, partial, unsupported, oversize, needs_ocr, encrypted, lfs_pointer, missing_dependency, parse_error, parse_timeout, fetch_error. done означает завершение обработки выбранной версии, а не подтверждение факта продажи. Partial сохраняет извлечённые сигналы и предупреждения.

Номер страницы поиска меняется только после сохранения найденных кандидатов. incomplete_results оставляет страницу на повтор. Дочерние size-поиски сохраняются в search_jobs; на следующем запуске добавляются к очереди. Лимит GitHub 1000, индекс и таймауты остаются материальными ограничениями.

Repos done означает прочитаны все выбранные кандидаты текущего snapshot. Это не весь GitHub, не все ветки и не каждый файл репозитория. Файлы, не выбранные фильтром расширения/пути, не объявляются проверенными. Предыдущие версии находок остаются доступными; актуальность не выводится из даты commit.

## Что улучшать следующим

1. Добавить OCR как отдельную опцию с Tesseract и явным статусом качества; сейчас сканы не распознаются.
2. Расширить правила извлечения русских конструкций «работал через X на проекте Y» на размеченных примерах; не соединять все компании из документа.
3. Добавить заголовки многоуровневых прайс-листов и более гибкое определение строк таблиц.
4. Добавить дедупликацию разных текстовых форм одного документа и пометку текущего/удалённого документа по snapshot.
5. При отдельном запросе — импорт результатов в существующий Laravel-инструмент пользователя. Не создавать новую CRM.

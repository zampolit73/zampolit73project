# IRLIX GitHub Intelligence v1.1 — изменения от 26.10.2026

- Старт от исторического исследования: 394 прогона, 416 уникальных репозиториев, следующий 395, цель ещё 49 671.
- Старые 416 репозиториев исключаются **по умолчанию**. Дополнительные исключения — `--exclude`; принудительный повторный обход — `--include-known`, **без увеличения счётчика**.
- SQLite добавляет `progress` и `verified_repos`: новые номера присваиваются в одной транзакции только после успешного чтения и анализа файла, не после одного поиска.
- Контекстно-ограниченный разбор TS/JS `TExperience` и HTML `timeline__item` портфолио. Источник и строчки сохраняются, связи между соседними проектами не склеиваются.
- В каждой находке независимый `sales_score` и `relationship_status`; автоматическая классификация не может доказать подписанный договор.
- Выгрузка `sales_buyers.csv` / `.json`, дополнительный сводный показатель количества лидов на 1 000 новых уникальных репозиториев. Это оценка *сигналов*, а не подтверждённых покупок.
- Сохранены все функции v1.0 по парсингу PDF, DOCX, XLSX, PPTX, GitHub Issues и перезапуска.
- **56 автоматических тестов** проходят; офлайн-демо прошло. Боевой веб-скан и VPS не подтверждены.

## Важные границы

Класс B = заявление участника/источника, не заверенный договор. `demand_current_confirmed` остается false. Историческая база №394 не загружается в `verified_repos`, а учитывается лишь в стартовом счетчике. Запуск на существующей базе SQLite версии 1.0 требует проверки или резервной копии: если она уже успела накопить новые после №394 проверки, нельзя дважды прибавить их к новому счетчику.

Репозиторий проекта публичен. В Git — только код, тестовые данные и список публичных `owner/repo`; ключи, реальные клиентские документы и локальные базы SQLite запрещены.

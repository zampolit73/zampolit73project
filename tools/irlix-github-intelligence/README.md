# IRLIX GitHub Intelligence 1.1 — Sales Edition

Бесплатный парсер публичных GitHub-репозиториев для поиска российских корпоративных покупателей IT-аутстаффинга и коммерческих сигналов. Работает на Windows и Ubuntu с Python 3.10+. Платные AI API, подписка на поисковик и Docker не нужны.

## Что получается

- Excel, CSV, JSON и HTML-отчёт с поиском по компании, стеку и тексту.
- Явно названные заказчик и подрядчик; отдельно — компании из CV и прочие упоминания.
- Ставки, валюта, единица расчёта, НДС, суммы договоров, зарплаты. Неизвестные значения остаются неизвестными.
- Номера договоров, даты в тексте, условия оплаты, ИНН юридических лиц с корректной контрольной суммой.
- Сигналы спроса по Java, .NET/C#, Python, Go, PHP, React, Vue, Angular, QA, аналитике, DevOps, Android/iOS, 1C и дизайну.
- Для каждой находки: цитата, ссылка на конкретный commit и файл, страница/строка, SHA256 содержимого, ограничения доказательства и действие для селза.
- SQLite-очередь, возобновление, журнал ошибок и отчёт о том, какие документы не удалось прочитать.

Это поисковая разведка: автоматическая находка не означает подписанный договор или актуальную закупку. Обнаружение всех документов GitHub гарантировать невозможно. Ограничения перечислены ниже и отражаются в отчёте.

## Запуск на Windows

1. Установите Python 3.10 или новее с python.org, при установке включите добавление в PATH.
2. Распакуйте весь архив, откройте PowerShell в папке с этим README.
3. Выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_windows.ps1
```

Скрипт создаст виртуальное окружение, установит зависимости и предложит: демонстрацию, поиск GitHub или обход списка репозиториев. При поиске он запросит GitHub token скрытым вводом. Он хранится только в памяти текущего процесса.

Проверка без токена:

```powershell
.\.venv\Scripts\python.exe -m irlix_intel local examples/demo --db data/demo.sqlite --out reports/demo
```

Все компании в демонстрации вымышлены; они помечаются классом X.

## Запуск на Ubuntu / Linux

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m irlix_intel doctor
```

Если нет модуля venv, установите пакет python3-venv средствами своей ОС. Для старого Excel XLS дополнительно нужен xlrd: python -m pip install 'xlrd>=2,<3'.

## GitHub token

Создайте персональный токен в настройках GitHub: https://github.com/settings/personal-access-tokens/new . Достаточен доступ для чтения публичных ресурсов; права записи парсер не использует. Для поиска кода fine-grained token не требует дополнительных разрешений согласно документации GitHub. Работоспособность проверяет команда doctor ниже. Токен не нужно присылать в чат, записывать в код или коммитить.

Linux / Bash, скрытый ввод на один сеанс:

```bash
read -rsp 'GitHub token: ' GITHUB_TOKEN
export GITHUB_TOKEN
python -m irlix_intel doctor --check-code-search
```

Без токена работают обход известных публичных репозиториев, поиск репозиториев и issues. Поиск по коду намеренно пропускается и остаётся в очереди. Анонимные лимиты существенно ниже. Парсер проверяет публичность репозитория перед чтением даже при наличии токена с более широкими правами.

## Основной поиск

```bash
python -m irlix_intel scan --profile quick --seeds config/seeds.txt --companies config/companies.example.json
```

Профиль quick содержит 12 запросов; deep — более широкий набор по договорам, ставкам, запросам, технологиям и текстовым форматам. По умолчанию один запуск ограничен 30 минутами, 600 запросами API, 20 репозиториями и 100 файлами на репозиторий. Это бюджет прохода, а не обещание проверить всё.

Продолжение — та же команда. Уже прочитанные версии файлов повторно не анализируются; незавершённые страницы поиска и документы остаются в очереди. Сначала обрабатывается накопленная очередь, затем выполняется поиск новых источников. Ctrl+C сохраняет накопленные результаты и формирует отчёт.

```bash
python -m irlix_intel scan --profile deep --max-queries 30 --max-repos 100 --max-files-per-repo 200 --max-api-requests 2000 --max-minutes 120
```

При лимитах API парсер ожидает разрешённое время либо завершает проход с кодом 2, сохраняя очередь. Код 2 — штатная пауза, код 1 — ошибка. Нет обхода ограничений аккаунтами или прокси. Защита от одновременного запуска с одной базой предотвращает гонки.

### Повторный мониторинг

```bash
python -m irlix_intel scan --profile deep --refresh-search --refresh-hours 24
```

Обычный запуск продолжает текущую очередь. Флаг --refresh-search начинает поисковые запросы с первой страницы, чтобы найти новые публикации. Завершённые репозитории перепроверяются после --refresh-hours; новое содержимое определяется по commit и blob SHA. Парсер не запускается сам по расписанию: при необходимости эту команду можно добавить в cron или Планировщик заданий Windows.

### Только выбранные репозитории

```bash
python -m irlix_intel scan --no-search --seeds config/seeds.txt
```

В seeds.txt укажите owner/repo по одному на строку. Наличие в seeds означает только интерес к проверке, а не доказанную коммерческую связь.

Файл config/previously_reviewed.txt содержит **416 уникальных репозиториев**, проверенных до серии №394 (26.10.2026). **По умолчанию они исключаются автоматически**. Новая проверка получает номер **№395** только после успешного чтения и разбора хотя бы одного файла в новом репозитории. Поисковая выдача, попытка открыть недоступный файл или просмотр пустого репозитория счёт не увеличивают. Для дополнительных исключений используйте:

```bash
python -m irlix_intel scan --exclude /path/to/my-extra-exclusions.txt
```

### Свои поисковые запросы

```bash
python -m irlix_intel queries --profile deep
python -m irlix_intel scan --queries config/queries.example.json
```

Запросы используют REST Search, не браузерный regex-поиск GitHub. Для широкого поиска кода с более чем 1000 результатов парсер создаёт более узкие запросы по диапазонам размера файла; они обрабатываются следующими проходами. Это уменьшает потери, но не отменяет ограничения индекса. Неполные ответы и насыщенные запросы отмечаются в search_coverage.csv. Для запросов репозиториев/issues уточняйте тематику вручную при превышении лимита.

### Уже скачанные документы

```bash
python -m irlix_intel local /path/to/documents --db data/local.sqlite --out reports/local
```

Режим local анализирует только указанную папку. Он не проверяет происхождение файлов и не приписывает им публичность или ссылку на GitHub. Используйте его для своих разрешённых документов. Оригиналы не изменяются.


### Быстрый запуск Sales Edition 1.1

```bash
python -m irlix_intel scan --profile deep --max-repos 50 --max-files-per-repo 100 --max-minutes 90
python -m irlix_intel status
```

- **По умолчанию исключены все 416 старых `owner/repo`.** Токен GitHub — только в переменной окружения `GITHUB_TOKEN`, никогда не в командной строке или в Git.
- `status` показывает новый `last_pass`, `next_pass`, `new_verified_repos` и прогресс от 50 000.
- **Новые файлы**: `reports/sales_buyers.csv` и `reports/sales_buyers.json`: короткий список потенциальных прямых заказчиков с именем поставщика, баллом коммерческого интереса и ограничениями подтверждения.
- `sales_score` оценивает *пригодность для Sales*, а `score` — качество/силу найденного сигнала. Это **не вероятность покупки**, и `B` не означает подписанный контракт.
- Новая эвристика разбирает отдельные записи структурированных CV (например `company.name = VK` вместе с `isOutstaff:true`) и HTML-портфолио (например `Citydrive — via RedLab outstaffing`). Связи между разными записями не соединяются.
- Для повторного мониторинга старых репозиториев без увеличения счётчика используйте `--include-known` (все 416 станут доступны для повторного сканирования).
- Исходная Excel-книга на 61 вкладке не перезаписывается: она находится в чекпоинте №394. Экспорт парсера создаёт **отдельную** книгу находок; автоматическое объединение в исторический XLSX в v1.1 пока не выполнено.

**Проверено локально:** 56 автоматических тестов и офлайн-обработка демонстрационных файлов; фактический GitHub API-прогон на VPS и расписание на сервере ещё не запускались.

## Как работать с результатом

Откройте reports/report.html или reports/findings.xlsx. Начинайте с высокого приоритета, проверяйте цитату и источник. Шкала 0–100 — сумма правил приоритизации, а не процент вероятности продажи. География RF_cue означает наличие признака РФ в тексте; RU_language_only означает только русский язык.

| Класс | Значение |
|---|---|
| B | Явное заявление о связи сторон или аутстаффинге в опыте сотрудника; подлинность и текущий статус не проверены |
| C | Косвенный сигнал: запрос, вакансия, кейс, клиентский список, неполный документ |
| D | Общее упоминание, методический материал, отрицательное заявление |
| X | Учебный, демонстрационный или синтетический материал |

Класс A автоматически не присваивается. Логотипы не подтверждают договор. Упоминания двух компаний рядом не образуют пару заказчик–подрядчик. Зарплаты не превращаются в клиентские ставки. Дата получения файла и дата commit не считаются датой спроса. Все найденные версии остаются в истории, поэтому старые записи нельзя автоматически считать действующими.

После ручной проверки можно сохранить решение:

```bash
python -m irlix_intel review FINDING_ID --verdict needs_followup --note "Проверить актуальность запроса у компании"
python -m irlix_intel review FINDING_ID --verdict confirmed_source_claim --note "Прочитан источник, содержание подтверждено"
```

confirmed_source_claim означает проверку содержания источника, а не наличие подписанного договора. Есть также verdict rejected. Решения хранятся по стабильному ID и сохраняются при повторной выгрузке. Ручные изменения самого XLSX обратно в SQLite не импортируются.

Другие команды:

```bash
python -m irlix_intel status
python -m irlix_intel export
python -m irlix_intel scan --retry-errors
```

В reports/ находятся findings.xlsx, findings.csv, findings.json, report.html, coverage.csv, search_coverage.csv, errors.csv, summary.json. В data/intelligence.sqlite — очередь, версии находок и ручные проверки. Скопируйте всю папку data при переносе на другой компьютер, остановив процесс перед копированием.

## Форматы и границы

- Поддерживаются PDF с текстовым слоем, DOCX, XLSX/XLSM, CSV/TSV, JSON/JSONL, Markdown/TXT, HTML, текстовые исходники и PPTX. XLS — с дополнительным xlrd.
- PDF-сканы помечаются needs_ocr; OCR в этой версии не выполняется. Старые DOC/PPT, RTF, ODT/ODS, картинки и архивы помечаются как требующие конвертации, если обнаружены по коммерческому имени. Git LFS pointers не выдаются за прочитанные документы.
- Для таблиц первая строка считается заголовком; сложные многоуровневые шапки требуют подготовки. Строки анализируются отдельно, чтобы не смешивать заказчиков и ставки. Отдельный факт из другого листа автоматически не присоединяется.
- Лимиты на файл: 5 MiB загрузки по умолчанию, 100 страниц PDF, 100 слайдов, 10 000 строк на лист/CSV, 60 столбцов листа, 10 000 фрагментов и 2 млн символов текста. Обрезание отражается в покрытии. Разбор одного файла ограничен 45 секундами и выполняется отдельным процессом.
- Обходится текущая default branch. Все ветки, вся история Git, комментарии issues, discussions, gists, внешние документы по ссылкам и изображения автоматически не обходятся. Внешние ссылки сохраняются без query-параметров, но не скачиваются.
- Поиск по коду ограничен индексом GitHub, в том числе небольшими файлами default branch. Поэтому второй этап обходит дерево найденного репозитория и проверяет документы напрямую. Репозиторий без поискового сигнала следует добавить в seeds.
- Это правила и регулярные выражения, а не полноценная языковая модель: возможны пропуски и ложные сигналы, особенно в свободном тексте и сложных таблицах. Подтверждение бизнес-связи остаётся отдельным шагом.
- API используется только на чтение. Токен не записывается в базу и не отправляется на внешние сайты. Оригиналы документов используются во временных файлах и удаляются; сохраняются метаданные, цитаты и хеши. Типовые email, российские телефоны и форматы API-ключей маскируются в цитатах; это не универсальный DLP.

## Проверка разработки

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют отделение зарплат от ставок, НДС, неизвестные единицы, границы записей, анонимных заказчиков, отрицания, роли сторон, синтетические примеры, DOCX/XLSX/PDF, возобновление, лимиты, неполный поиск, обход больших деревьев и защиту экспорта от формул/HTML.

Подробности реализации и подтверждённые проверки — в docs/ARCHITECTURE.md и docs/VALIDATION.md.

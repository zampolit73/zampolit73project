# IRLIX Sales Intelligence — GitHub Outstaff РФ
Контрольная точка: 2026-10-25. Только публичные источники GitHub. Ветка изолирована от `main` и не предназначена для деплоя.

## Цель и ограничения
Исследование находит российских покупателей IT-аутстаффинга, публичные отношения «заказчик — подрядчик», признаки спроса, тендеры и ставки для отдела продаж. Это **MVP коммерческой разведки**, а не CRM. Не создавать парсер, не подключать CRM и не расходовать бюджет без отдельной команды пользователя. Технические технологии: Java, C#, PHP, Python, Go, React, Vue, Angular, QA, системные и бизнес-аналитики, iOS/Android, DevOps, 1С.

## Правило проверки и дедупликации
1. Сверить `owner/repo` (без учёта регистра) со всем `REPO_EXCLUSIONS.txt`.
2. **Один впервые открытый и реально прочитанный репозиторий = максимум один новый номер прогона.** Разные файлы внутри того же репозитория — дополнительное доказательство, не новый прогон.
3. Поисковая выдача, случайное упоминание имени фирмы, логотип, новость или учебный код НЕ являются подтверждением клиента.
4. Для каждого проверенного источника указать: номер, точный URL GitHub, путь к файлу, дату/период, фактически прочитанный фрагмент, компании/роли/стек, денежные единицы и НДС при наличии, класс доказательности, вывод и рекомендацию Sales.
5. Вносить в одну накопительную книгу после каждой проверки; сохранять checkpoint. Состояние хранить как отдельные машиночитаемые CSV/JSON.
6. Не собирать и не публиковать личные email/телефоны кандидатов, персональные данные, закрытые коммерческие условия и секреты.

## Классы доказательности
- **A:** официальный контракт, подтверждённая закупка или первичный коммерческий документ.
- **B:** прямое заявление участника и конкретный процесс аутстафф-отбора; договор не обязательно заключён.
- **C:** вторичный источник, портфолио, косвенная заявленная клиентская связь.
- **D:** технология, парсер, справочник, аналитика без фактического заказа.
- **X:** учебные/тестовые данные, демо, ошибки, нерелевантные/неподтверждённые утверждения.
